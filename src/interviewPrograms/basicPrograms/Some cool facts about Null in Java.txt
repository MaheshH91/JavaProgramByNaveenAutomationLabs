###  **Cool Facts About `null` in Java**

#### 1. **`null` is a literal, not an object**
- It’s the only **literal** in Java that represents the absence of a value.
- You can assign it to any reference type, but not to primitives like `int`, `double`, etc.

#### 2. **`null` has no type—but it’s type-compatible**
- Though `null` itself has no type, it can be assigned to any reference type:
  ```java
  String s = null;
  Object o = null;
  List<String> list = null;
  ```

#### 3. **Calling a method on `null` causes `NullPointerException`**
- Classic mistake:
  ```java
  String s = null;
  s.length(); // Throws NullPointerException
  ```

#### 4. **You can compare `null` using `==` but not `.equals()`**
- `null == null` is `true`
- `null.equals(...)` throws an exception if the caller is `null`

#### 5. **`instanceof` returns `false` for `null`**
- Even if the reference is of a known type:
  ```java
  String s = null;
  System.out.println(s instanceof String); // false
  ```

#### 6. **`null` can be cast to any reference type**
- But using it afterward will still throw `NullPointerException`:
  ```java
  Object obj = null;
  String str = (String) obj; // Valid cast
  ```

#### 7. **You can overload methods with `null` as argument**
- But it can cause ambiguity if multiple overloaded methods accept different reference types:
  ```java
  void print(String s) { ... }
  void print(Integer i) { ... }
  print(null); // Compile error: ambiguous
  ```

#### 8. **`null` is not a keyword—but it’s reserved**
- It’s a **literal**, like `true` and `false`, but not a keyword like `class` or `public`.
